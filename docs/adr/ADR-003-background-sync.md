# ADR-003 — 背景同步而非即時 API 呼叫

> 狀態：已採用 | 日期：2026-09-20

## 背景

銀行 API 速率限制嚴格（部分台灣 Open Banking 每小時僅允許數十次呼叫）。需決定何時呼叫銀行 API：用戶請求時即時呼叫，或背景定時同步。

## 決策

採用背景同步模式：
- Vercel Cron 每 6 小時觸發 `POST /api/internal/sync`，拉取所有 active 連結的最新資料存入 PostgreSQL
- 用戶瀏覽 Dashboard / 交易列表時，讀取 DB 快照（可加 Redis 快取）
- 用戶可手動觸發重整（每 5 分鐘限一次）

## 理由

- **不阻塞用戶請求**：銀行 API 可能需 2-5 秒；後台同步讓 Dashboard 載入時間僅受 DB 查詢影響
- **保護速率配額**：集中管理呼叫頻率，避免多用戶同時觸發超出配額
- **容錯性**：銀行 API 暫時不可用不影響用戶讀取歷史資料

## 取捨

- 資料最多延遲 6 小時（用戶看到的不是即時餘額）；用戶可手動重整取得最新資料，SPEC 已接受此設計
- 需維護 Cron Job；Vercel Cron 免維運，可接受

## 替代方案（排除）

- **即時呼叫**：每次 Dashboard 載入都打銀行 API，延遲高且耗盡速率配額

## 回復方案

若用戶對資料即時性有更高需求，可縮短 Cron 間隔（最短 1 小時）或提升手動重整頻率上限。
